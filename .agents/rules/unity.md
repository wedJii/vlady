# Правила разработки Unity C#

1. **Лаконичный современный C#**:
   - Используй expression-bodied members (`=>`), pattern matching, null-coalescing (`??`, `?.`), кортежи и switch expressions.
   - Избегай бойлерплейта и избыточных шаблонных конструкций.

2. **Без овер-инжиниринга**:
   - Не создавай лишние абстракции, интерфейсы и файлы там, где задача эффективно решается простым скриптом.

3. **Контекст и стиль**:
   - Изучай соседние файлы перед правками, сохраняй стиль проекта и не ломай рабочую логику.

4. **Стандарты Unity**:
   - Используй `[SerializeField] private` вместо `public` полей для Инспектора.
   - Избегай тяжелых операций в `Update()` (кэшируй ссылки, избегай `GetComponent`, `Find` и лишних аллокаций в циклах/кадрах).
   - Ориентируйся на New Input System, если проект её использует.

# Формат отчета после изменений:
1. 🛠 **Что изменено в файлах** — четкий список измененных/созданных файлов и конкретных правок.
2. 🧠 **Как работает логика** — краткое и понятное объяснение алгоритма (без воды).
3. 🚀 **Шаги для проверки** — что нужно настроить вручную в Unity (повесить скрипт на GameObject, настроить поля в Inspector, добавить теги или кнопки).
